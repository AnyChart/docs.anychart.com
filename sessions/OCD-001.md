### Design Work — Two Iterations

- [x] **v1 (rejected):** Multi-branch deployment — N separate builds at `/DVF-XXXX/` paths. Rejected because HTML has baked-in `baseUrl`, can't mix pages across versions, complexity scales with branch count.

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| **Three-layer model** (prod / staging / archives) | Simpler than per-branch deployments; staging aggregates all DVF changes; diff highlighting is the real feature |
| `docs.anychart.com` = production | Public, current release |
| `docs.anychart.stg` = staging | Auth-gated release preparation with diff highlighting |
| `/v7/`, `/v8/` = version archives | Major releases only, frozen snapshots |
| v9+ = per-minor versioning | New era with proper version switching (9.0.0, 9.1.0, etc.) |
| Cross-repo automation | Push DVF branch to AnyChart/AnyChart → auto-create matching docs branch |
| Branch-aware edit flow | "Suggest Change" on staging targets staging branch |
| OCD session system | Adapted from Rolodex; not tied to git branching |
| API reference deferred | Seal docs end-to-end first |
