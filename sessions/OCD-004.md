# OCD-004: Staging Features — Local Implementation

**Date:** 2026-02-26 (planned)
**Status:** Planned

---

## Session Objective

Implement the staging-specific features that make the three Docker environments actually behave differently. Currently the containers build from different branches but the app itself doesn't use `IS_STAGING` for anything.

## Context Before Session

- OCD-002: Docker infrastructure done — 3 containers running (prod :8080, staging :8081, DVF :8082)
- OCD-003: Content audit done → BACKLOG.md created, content work deferred
- `IS_STAGING` env var passes into build but app ignores it
- `ANYCHART_VERSION` works (preprocessor replaces `{{branch-name}}`)
- Server work postponed — DevOps handling new server
- All work is local, no deployment

## Proposed Work

### 1. Wire Up IS_STAGING in Docusaurus

Make the app aware of its environment:
- Read `IS_STAGING` as a Docusaurus custom field or env var
- Make it available to React components at build time

### 2. Staging Banner

When `IS_STAGING=true`:
- Show a persistent banner at top: "Staging Environment — [branch/version info]"
- Visually distinct from production (different accent color or background)

### 3. Category Landing Pages (from BACKLOG.md)

Quick structural fix — no content writing needed:
- Switch 28 `_category_.json` files from `generated-index` to `type: doc` pointing at existing overview.md
- Verify sidebar still works correctly after the change

### 4. Diff Highlighting Foundation (WS-3)

Start the build-time diff system:
- Script that diffs markdown files between two branches (e.g. gogin-AI-refactor vs gogin-AI-refactor-STG)
- Output a `diff-manifest.json` listing changed files + changed sections
- React component that reads the manifest and highlights changed content on staging

### 5. Branch-Aware Edit Flow (WS-4)

Make "Suggest Change" know its context:
- Detect environment from `IS_STAGING`
- Route PR to correct base branch (staging → develop, production → develop)
- Show environment context in editor

## Prerequisites

- Docker Desktop running (for testing across 3 containers)
- All 3 branches exist: gogin-AI-refactor, gogin-AI-refactor-STG, gogin-AI-refactor-DVF

## Success Criteria

- [ ] Production container (:8080) looks and behaves exactly like today
- [ ] Staging container (:8081) shows staging banner + any diff highlights
- [ ] Category pages use real overview docs instead of auto-generated lists
- [ ] Edit flow knows which environment it's in
